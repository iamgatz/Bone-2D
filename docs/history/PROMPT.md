# Bone 2D — самопромпт (мастер-инструкция для реализации)

> Этот файл я написал сам себе. Он — источник правды: что строим, на чём, в каком порядке и когда считать готовым.

## 1. Миссия

Построить **Bone 2D** — браузерный редактор 2D-скелетной анимации уровня Spine: кости, слоты, меши с весами, IK и
transform-констрейнты, таймлайн с кривыми Безье, скины, события, порядок отрисовки, экспорт.
Всё работает **целиком в браузере** (как Figma): открыл ссылку — рисуешь и анимируешь, ничего не ставя.

Ключевое требование совместимости: экспорт в **Spine JSON 4.3** (+ `.atlas` + PNG), который без правок грузится
официальными рантаймами `spine-ts` / Unity / Godot / Pixi и т.д. Это доказывается автотестом: наш экспорт загружается
официальным `@esotericsoftware/spine-core@4.3.x`, и мировые трансформации костей / вершины мешей совпадают с нашим
собственным солвером на десятках моментов времени.

Весь код — наш собственный (идеи и формат общие, реализация своя).

## 2. Что показало исследование (кратко, подробности — RESEARCH.md)

- Актуальная версия Spine — **4.3** (stable 14 мая 2026): слайдеры, переработанные transform-констрейнты
  (маппинг свойство→свойство, clamp, local/world), draw-order folders с ключами, inverse/convex clipping,
  linked mesh в другом слоте, volume-preserving scaleY у IK/physics, per-skin атласы.
- Документация JSON на сайте **устарела** (описывает 3.8). Реальный формат 4.3 взят из исходников рантайма
  (`SkeletonJson.ts` ветки 4.3): единый массив `constraints` с полем `type`, `inherit` вместо `transform`,
  кривые как массив `[cx1,cy1,cx2,cy2]` на канал (X — секунды, Y — значение), `value` у одноканальных таймлайнов.
- Рантайм аппроксимирует Безье 10 отрезками (BEZIER_SIZE=10) — повторяем **ту же аппроксимацию**, чтобы
  картинка в редакторе совпадала с картинкой в игре.
- Конкуренты (SkelForm, Rigby2D, keyframe.it, Rive, DragonBones) либо десктопные, либо без меш-весов/IK-экосистемы,
  либо мертвы. Наша ниша: **браузер + совместимость со Spine 4.3**.

## 3. Стек (решение и почему)

| Слой | Выбор | Почему |
|---|---|---|
| Язык | TypeScript strict | Один язык для ядра, UI, тестов; ядро без DOM работает в Node/браузере |
| Сборка/dev | Vite + React 19 | Быстрый HMR; React только для «хрома» (панели, меню, инспектор) |
| Холст | **Свой WebGL2-рендерер** + Canvas2D-оверлей | Нужны скиннинг-меши, blend-режимы, тинт; готовый движок избыточен. Тот же рендерер переиспользуется в плеере. Оверлей (кости, гизмо, сетка, текст) на Canvas2D — чёткие линии и просто |
| Состояние документа | **Immer patches** | Undo/redo бесплатно: каждая правка — функция-мутация; патчи схлопываются по жестам (drag = 1 запись) |
| Состояние UI | крошечный store + `useSyncExternalStore` | Режим, инструмент, выделение, камера, время — не в истории |
| Триангуляция | `delaunator` + свой трейсер альфы | Автомеш по контуру изображения |
| Упаковка/ZIP/кривые/IK | свои (MaxRects, store-ZIP, solver) | Ноль лишних зависимостей, полный контроль, совпадение с рантаймом |
| Иконки/шрифт | `lucide-react`, Inter (fontsource) | Аккуратный «профессиональный» вид |
| Тесты | Vitest + дифф-тест против официального `spine-core` 4.3 (dev-зависимость) | Доказательство корректности формата и математики |
| Сохранение | `.bone2d` (JSON, картинки base64) + IndexedDB автосейв + File System Access API | Работает офлайн, без бэкенда |
| Позже (опционально) | Rust→WASM для горячих мест; Tauri-упаковка; CRDT-совместная работа | Архитектура ядра это допускает |

## 4. Архитектура

```
src/core      чистая логика (без DOM): math, model, curve, skeleton(pose+solve), animate, mesh, trace, export/*
src/store     document store (immer, история), ui store, actions (все мутации документа)
src/render    WebGL2: batch, textures, skeleton renderer; Canvas2D overlay
src/editor    React-панели: Tree, Inspector, Assets, Animations; Viewport (+tools); Timeline (dopesheet, graph)
tests         vitest: core + дифф-тесты
docs          PROMPT / RESEARCH / PLAN
```

Принципы:
1. **Документ = обычный JSON** (кости/слоты/скины ссылаются по `id`, не по имени → переименование безопасно).
2. **Компиляция в runtime-данные** (`compileSkeleton`): индексы, плоские массивы; кэш по ссылке (WeakMap) —
   неизменённые аттачменты не перекомпилируются.
3. **Таймлайны хранятся в Spine-совместимом виде**: ключ = `{time, value[], curve}`, `curve` = `undefined`(linear) |
   `'stepped'` | `number[]` (по 4 числа на канал). В документе Безье нормализован (0..1 относительно сегмента), в
   экспорте переводится в абсолютные секунды/значения.
4. **Порядок обновления** (update cache) повторяет рантайм: кости в иерархии, констрейнты в заданном порядке,
   зависимости сортируются.
5. UI-слой не знает про математику; математика не знает про UI.

## 5. Дизайн-цель UI

Тёмный профессиональный редактор уровня Figma/Rive/Linear: чёткая сетка, один акцентный цвет, плотные но дышащие
панели, hover/active/focus состояния, горячие клавиши, всплывающие подсказки, ресайз панелей. Никаких «заготовок»:
каждая кнопка должна работать.

Раскладка: сверху тулбар (режим Setup/Animate, инструменты, undo/redo, play); слева дерево + ассеты; по центру
вьюпорт; справа инспектор; снизу таймлайн (dopesheet / graph).

## 6. Объём (в порядке приоритета)

**P0 вертикальный срез** — проект, модель, undo, рендерер, импорт PNG, кости (создание/правка), слоты+регионы,

## 7. Рабочий процесс (жёсткие правила для меня)

1. Идти **вертикальными срезами**: каждый срез собирается, тестируется и проверяется в браузере до перехода дальше.
2. После каждого среза: `tsc --noEmit` → `vitest run` → открыть в Browser-панели → скриншот/DOM-проверка.
3. Баг не прячется — чинится у причины. Падающий тест не «подгоняется», а разбирается.
4. Не изобретать числа/формат — сверять с исходниками рантайма 4.3 (скачаны в research/).
5. Не писать лишнего: новая абстракция — только когда два места уже её просят.
6. Фоновые задачи не поллить — ждать уведомления.
7. В финале честно сообщить: что сделано, что проверено, что осталось.

## 8. Definition of Done (для этой сессии)

- `npm run build` и `npm test` зелёные.
- В браузере: импорт картинок → кости → слоты → ключи → воспроизведение → сохранение/загрузка → экспорт ZIP.
- Меши с весами и IK работают и анимируются.
- Дифф-тест против официального spine-core 4.3 проходит на эталонном скелете (кости + меши с весами + IK + анимации).
