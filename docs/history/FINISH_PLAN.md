# План доведения ВСЕХ пунктов до конца

Правило: в этом списке ничего не откладывается «на потом» и не отвергается без причины. Пункт закрывается только когда: код есть, тесты есть (и операция в фаззере, где это уместно), ru-строки есть, changelog / README / IDEAS / memory обновлены, `main` обновлён (`git push origin ui:main`, только noreply-личность). Если пункт нельзя сделать полностью (нет описания формата, нечем проверить), в строке пишется конкретная причина и что сделано вместо, и пункт всё равно помечается `[x]` с пометкой «частично: …».

Единственное, что остаётся за пользователем: проверка бинарного 4.0–4.2 на его файлах (`node tests/fixtures/record-legacy42.mjs <папка> --write`). Обходить отказ в разрешении нельзя.

## Порядок работы на каждом шаге цикла

1. Прочитать этот файл, взять первый невыполненный пункт.
2. Сделать полностью (код, тесты, фаззер, ru, changelog, README, IDEAS, SPINE_PARITY, memory).
3. Перед запуском фаззера и общего прогона НЕ править исходники до уведомления.
4. Закоммитить и `git push origin ui:main`, отметить пункт `[x]` здесь.
5. Когда все пункты кроме C1 закрыты: остановить цикл и написать итог по-русски.
