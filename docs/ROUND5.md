# Bone 2D — раунд 5: интерфейс, дизайн-система, демо-риг

Заказ владельца (2026-11-17): «если нет срочного — немного заняться интерфейсом, UI/UX, дизайн-системой; загрузочный демо-риг можно сделать сильно лучше».
Срочное (блок C: разбор fuzz, мутанты, слияние) закрыто раньше; блоки D–F плана ROUND4 идут после этого раунда (порядок: E → D → F).

Правила: данные и `src/core` не трогаем (раунд про вид и удобство); EN + RU обязательны (`tests/i18n.test.ts`); после каждого шага — `tsc`, `vitest`, `npm run build`,
проверка глазами в браузере (EN и RU, узкое окно), потом коммит.

## 1. Аудит (факты на 2026-11-17)

- `src/styles/app.css` — 1090 строк. Токены есть только для цвета / радиуса / шрифта / тени (`--bg … --danger`, `--radius`, `--font`, `--shadow`); **нет** шкал отступов,
  размеров контролов, типографики, z-index, длительностей.
- Инлайн-стилей `style={{…}}` — **112 блоков в 14 файлах** (InspectorPanel 20, Timeline 16, TreePanel 14, MeshInspector 11, GraphEditor 9, PhysicsConstraintInspector 7, ExportDialog 7 …).
- Захардкоженные цвета вне токенов: ~25 (Dopesheet и GraphEditor рисуют на canvas, `App.tsx` 4 раза `#31d0aa`, иконка физического инспектора).
- `src/editor/ui/controls.tsx` (12 компонентов: IconButton, Button, Toggle, NumberField, TextField, SelectField, ColorSwatch, Menu / MenuItem, Dialog, Splitter) **не имеет**:
  строки «метка + контрол + ключ ◆» (каждый инспектор объявляет свой локальный `Row`), сворачиваемой секции, сегментного переключателя, подсказки с горячей клавишей
  (везде нативный `title`), единого списка горячих клавиш.
- Демо-риг «Bolt» (`src/store/sample.ts`): робот на ~20 костях из region-ов, две IK-ноги, idle + walk. **Нет** мешей / весов / деформации, physics, path, скинов, событий,
  draw order — то есть витрина показывает половину редактора. Рисуется canvas-кодом при старте (хороший принцип, оставляем).

## 2. План

      Все инспекторы (кость, слот, регион, полигон, путь, точка, IK, трансформ, слайдер, путь-констрейнт, физика, меш) переведены на `Field` / `Section`; шапка констрейнта (вид, порядок, удалить, имя) — один компонент

### D. Новый демо-риг
Принцип: **чистый построитель** `buildDemoRig(images)` (кости, меши, констрейнты, скины, анимации — без DOM, на вход размеры картинок) + тонкий `loadSample()` (canvas-арт → PNG → assets).
Тогда риг проверяется в vitest как любая фикстура: `validateProject` чистый, экспорт принимает официальный загрузчик, позы совпадают с официальным рантаймом, physics играется кадр за кадром.
- [ ] D1 Персонаж «Kit» — зверёк с пушистым хвостом, шарфом и ушами: тело и голова — меши с весами, глаза — моргание (деформация / смена attachment), руки и ноги — IK,
      хвост / шарф / уши — physics, два скина (цветовые варианты), draw-order ключ (лапа за / перед телом), события (шаги).
- [ ] D2 Анимации: idle (дыхание, моргание), walk (петля с IK и качающимся хвостом), wave (приветствие), jump (приседание — прыжок — приземление, reset-ключ физики на склейке).
- [ ] D3 Арт: процедурный canvas (градиенты, мягкие тени, единая обводка), без внешних файлов и лицензий; палитра из токенов бренда.
- [ ] D4 Тест `tests/demo.test.ts`: построитель с фиктивными размерами картинок → валидатор, экспорт + официальный загрузчик, позы в нескольких точках всех анимаций, physics 40 кадров.
- [ ] D5 Подача: при загрузке сайта — Setup-вид, сразу играет idle; подсказка «потяни кость / переключи в Animate»; кнопка «Загрузить демо» в приветствии.
