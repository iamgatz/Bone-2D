## Отвергнуто и почему

Из продуктового разбора 2026-11-19 (по заявкам аниматоров на форумах Spine, Rive, Live2D, Moho). Сделанное описано в разделах «Сделано» ниже.

- **Живая совместная правка (несколько человек сразу).** Нужен сервер сигналов и слияние правок (CRDT); у нас статический хостинг, проверить правильность слияния нечем, а риск испортить чужой проект высок. Вернёмся, если понадобится именно присутствие, а не обратная связь (она закрыта страницей ревью).
- **Авто-риггинг и веса «одной кнопкой».** Качество не проверить тестами, плохой авто-результат хуже ручного.
- **Предпросмотр на телефоне по QR-коду.** Без сервера-посредника нужен прямой канал между устройствами (WebRTC), то есть тот же сервер сигналов; для просмотра есть страница-плеер как файл.
- **График скорости.** Заявка одного человека; скорость по производной кривых легко прочесть неверно (у ключей с кривой по каналам она разная), риск вводящего в заблуждение графика не окупается.
- **Править интерфейс «вообще»** (переставить панели, поменять цвета). Нет подтверждённой боли и нечем проверить.

## Сделано в v0.52 (2026-11-19)

Слой сверху (запекание аддитивной анимации в новую), плавная смена картинок через слот-партнёр, страница-плеер одним HTML-файлом. Не сделано из этого: слой складывается только для костей (слоты, деформация, события и констрейнты остаются из первой анимации); слой не живой, а запекается, так что при правке слоя запекание надо повторить; плавная смена не работает для слота с тёмным цветом или с ключами цвета, партнёр не получает ключей деформации и последовательностей, ключи порядка отрисовки не знают о слоте-партнёре; плеер показывает скелет редактора (без смешивания анимаций друг с другом и без таблицы миксов), а не экспорт Spine через официальный рантайм; цвет вершин и смещение UV не делаем (формат Spine их не знает).
